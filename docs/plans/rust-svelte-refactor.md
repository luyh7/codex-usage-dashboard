# Rust 核心与共用前端重构实施方案

本文件给实施 agent 使用。目标是保留当前统计语义和安装入口，改为可供浏览器版、未来 macOS/Windows 客户端复用的 Rust 核心，并解决长时间线和大量会话下的交互延迟。

## 先读与执行约束

1. 阅读仓库 `AGENTS.md`、[实测报告](../performance/refactor-evaluation.md) 和 `benchmarks/refactor/results/verification.json`。先核对当前 HEAD、生产脚本 SHA256 与报告是否相符；不符则记录差异并重跑受影响基准。
2. 从 `git status --short` 识别用户已有改动。评估开始前 `docs/research/startup-options.md` 已存在且未跟踪，保留其内容。生产入口仍是 `skills/codex-usage-dashboard/scripts/codex_usage_dashboard.py`。
3. 每批代码变更后从当前 worktree 运行 dashboard，固定 `127.0.0.1:8765`。确认占用进程属于本项目才优雅替换。每阶段结束验证 `/api/health` 和实际页面来自当前构建。
4. 保留日志只读、本地运行、现有手动快照数据。测试使用合成或明确脱敏的 fixture；日志内容不进入提交、报告或默认诊断上传。
5. benchmark 原型用于验证设计，不直接复制为生产实现。它有固定时区、部分时间语法、部分归一化等限制，详见报告。

完成标准：交付兼容的浏览器版、独立 Rust 核心、可静态构建的前端、可重放的正确性和性能证据，以及升级/回退说明。Tauri 外壳为后续独立阶段；核心与前端必须先具备复用条件。未运行的 macOS/Windows 检查明确标为未通过，不能以 WSL 结果替代。

## 已据实测确定的决策

- 优先解决详情事件表的首次渲染规模，保留全量数据查询/导出；单纯换框架不能消除业务计算成本。
- Rust 用强类型 `Usage`、事件、计价与查询结果；借用或共享不可变数据。大范围 `serde_json::Value` 克隆在本次汇总、时间线实验中出现性能倒退。
- 保留追加解析、文件库存缓存、持久解析缓存、快照 token、一致性详情与远程缓存。已有无变化刷新通常很快。
- WSL Windows 挂载盘作为独立性能场景。原生 watcher + 轮询兜底，分层 metadata 检查、较大顺序读取 buffer 必须实测。
- 前端采用 Svelte + TypeScript + Vite 静态 SPA；依据是维护与组织方式。本实验没有证明 Svelte 比 React/Vue 快，也不引入前端 Rust/WASM。
- Axum 和 Tauri 是两个宿主适配；日志解析、计价、查询不依赖任何一个宿主。数据库存放在宿主本地配置目录。

## 目标结构与接口

建议 Cargo workspace + 独立 web 工程；已有 npm 安装入口继续保留。

```text
crates/
  usage-core/       # 解析、归一化、计价、索引、查询；不依赖 HTTP/Tauri
  usage-server/     # Axum、CLI、静态资源、固定端口生命周期
web/
  src/lib/data/     # 查询类型、HTTP adapter、后续 Tauri adapter
  src/lib/domain/   # UI 所需的纯派生逻辑
  src/components/  # 项目树、指标、筛选、详情、日历、远程管理
desktop/           # 后续 Tauri 宿主；阶段 7 才引入
benchmarks/refactor/ # 保留本次实测来源
tests/fixtures/    # 可公开的 golden 输入/输出
```

核心公开接口应围绕少量操作设计：

- `query_sessions(query, cursor, revision)`：筛选、稳定排序、分页摘要；返回完整筛选集合的指标、分页和 revision。
- `query_project_tasks(query, project, cursor, revision)`：项目聚合与任务组分页；页面边界不能拆散主任务身份。
- `query_session_detail(id, range, revision)`：元数据与概览。
- `query_events(id, range, cursor, revision)`、`query_chart(id, range, resolution, revision)`：事件明细与图表分开。
- `query_daily_usage(range, timezone, revision)`：日历状态与聚合值。
- `import_snapshot`、`export_snapshot`、`manage_remote`：保留 v1 兼容语义。
- `subscribe_revision`：变更 revision 通知，客户端据此取数据；重连要重新校验。

后端拥有索引更新周期。页面只查询已经发布的数据，状态区显示索引进度和更新时间。HTTP 请求中不执行全量重建。异步宿主中的 CPU/阻塞 I/O 工作交给有上限的工作线程。

## 阶段 0：冻结兼容合同与基线

输入：当前生产代码、90 项原有测试、性能报告与原始输出。

操作：

1. 将既有测试中的小型日志抽取为语言无关 fixture，保留可人工核算的期望值。覆盖独立会话、续写文件、父子多层代理、缺失父节点、计数器 reset、runtime service tier、工具调用、归档移动。
2. 冻结现有 HTTP 响应、导出 schema/version、设备身份与配置目录行为；记录允许变化的内部字段。临时路径、生成时间、顺序等差异必须逐项定义，不能整个字段树忽略。
3. 计数与用量逐项精确比较；费用保留现有六位小数结果与 rounding 行为。先复现当前行为，再独立修复已确认的缺陷。
4. 将全链路场景加入基准：首次打开、重启缓存恢复、追加一条事件、修改历史价格、打开长会话、切换日期、导入远程快照、4 客户端并发、空闲运行。

完成条件：Python 生成的 golden 结果可由独立比较器重放；现有测试全绿；原始基线数据与机器/版本/样本规模同存。基准不读取用户内容。

## 阶段 1：先交付前端高收益改动

输入：旧后端；保持功能可用。

操作：

1. 详情事件表首次只渲染 100 条，提供前后页或加载更多，显示总条数。逐步切换到后端 cursor 分页，避免仅减少 DOM 却仍传输完整大时间线。
2. 图表接口与事件表分离，初始实现保留完整曲线；若下采样，明确保留时间顺序、极值和端点，并验证误差。当前曲线绘制本身很快，先避免整表生成。
3. 建立每条会话的可搜索文本索引，数据变更时仅更新受影响项。过滤后的集合、汇总、项目分组在一次数据/查询 revision 内复用。
4. 选择会话、折叠项目和展开代理只更新相关 UI；保留滚动、焦点、选择与展开状态。继续尊重现有 204 跳过刷新行为。

完成条件：筛选结果和合计与旧实现相同；10k 事件所有页合并无遗漏、无重复；最新页与导出一致；项目/代理展开和键盘操作可用；性能报告单列算法/工作量收益，不标作 Rust 加速。

## 阶段 2：迁移 Rust 解析与领域计算

操作：

1. 定义 `Usage`、`RawEvent`、`NormalizedEvent`、`SessionIdentity`、`PriceSchedule`、`PriceSegment`。明确整数范围及溢出处理，未知模型或未知档位保留 unknown，不能当作零费用。
2. 流式 JSONL 读取，保留 BOM、非法 UTF-8 策略、坏行计数、完整/未完成末行语义、忽略大输出的条件和已消费字节数。添加超大行与不同 JSON 布局测试。
3. 实现完整 `parse_file` 语义：标题过滤、metadata 优先级、模型与 effort、任务耗时、工具调用、runtime tier 合并。fixture 中每个公开字段都要比较。
4. 独立实现续写片段合并、父子代理继承去重、spawn 时档位继承和缺失父节点状态。维护依赖图，父节点变化时更新关联子图；不能只给当前文件做局部相减。
5. 迁移历史计价表为有版本的数据资产；按事件发生时间和请求输入长度选择价格，再聚合 segment。价格变化触发重计价，不重新读原日志。reasoning 是 output 子集，不能额外累加费用。
6. 事件差分和归一化结果只计算一次，并供计价、期间统计、日历使用。禁止为了减少一次计算而丢掉归一化前后语义区别。

完成条件：所有 golden fixture 的所有公开字段通过；本次价格边界全集（规模见 correctness.json）及 fuzz 扩展通过；Rust 溢出、无父节点、部分写入、异常编码测试通过。重新跑对象版与强类型基准确认实际生产路径没有退回通用 JSON 克隆。

## 阶段 3：持久索引与后台更新

操作：

1. 建立文件身份、读取偏移、原始归一化事件、会话关系、会话摘要、日历聚合和索引元信息。时间线索引至少包含 session identity + timestamp + 稳定事件顺序。
2. 区分原始累计计数、请求 delta、去继承后的 delta，保持可重算来源。先确定跨源身份策略；远程与本地同 session_id 不能无条件合并。
3. 单个事务内提交事件、摘要、读取偏移和 revision。崩溃恢复不得产生“偏移已前进、事件未写入”。写者串行，查询读取一致 revision；长事务与 checkpoint 行为可观测。
4. 文件新增、追加、截断、等长替换、mtime 未变、归档移动、依赖补齐分别设计失效规则。全量巡检作为兜底，活跃文件优先；WSL watcher 丢事件时靠轮询恢复。
5. 缓存存放在运行宿主的本地文件系统；日志可以在挂载盘。先保护已验证的历史文件 metadata 缓存，再优化原生路径。
6. 日期按 UTC 事件存储、指定显示时区计算边界；分别测试 DST、午夜边界与切换时区。不要将本次固定 UTC+8 原型直接上线。
7. 版本化 schema/parser/pricing，并实现可丢弃重建的索引。远程快照属于用户数据，升级保留原件，不能和可丢弃缓存同样处理。

完成条件：在每个提交阶段模拟崩溃并恢复；同一日志重复扫描用量不增长；所有失效场景下一次/约定刷新内可见；旧 revision 详情要么一致返回，要么明确 stale；索引构建与增量写入开销单独实测。

## 阶段 4：接入 Axum 与旧入口

操作：

1. 保留 `/api/health`、现有列表/详情、日历、远程 CRUD 和 export；新分页接口可使用独立路径或版本，不静默改变旧消费者响应。
2. 查询和分页使用稳定排序，cursor 绑定筛选与 revision。指标统计整个筛选集合，不能只加当前页。项目汇总和父子代理不能重复计数。
3. SSE 只传 revision/进度，订阅断开可恢复；无变化不触发页面重算。保留低频轮询校验并测试断线重连。
4. health 返回版本、build/source 标识、核心能力、索引状态。启动入口按协议版本识别兼容性，保留固定 8765 与进程身份确认。
5. 保留 CLI、skill、导出与桌面快捷方式入口。CPU 密集解析不会阻塞健康检查与已索引查询。

完成条件：旧 HTTP 合同与 Python/Rust 双实现集成测试通过；真实 8765 完成列表、日期切换、详情、204/stale、导出和远程导入重命名删除往返；并发查询期间数据一致；关闭进程能释放端口。

## 阶段 5：Svelte 前端与界面整理

操作：

1. 抽出 `DashboardData` 接口与类型，提供 HTTP adapter；页面中不直接散落 fetch 或宿主调用。查询取消、过期响应丢弃、revision 一致性在数据模块统一处理。
2. 使用有稳定 key 的组件表达项目、任务、代理与详情；生产组件用模板转义用户文本，不沿用 benchmark 的原始 HTML 注入方式。大型不可变数据避免无必要的深层响应式包装。
3. 默认四项指标：总 tokens、预估费用、会话数、缓存命中率。输入/输出细分展开显示；预估费用、unknown、索引未完成要有文字区分。
4. 筛选工具栏保留搜索、时间和筛选入口；生效条件可移除。详情侧栏可收起，窄窗口适配，数字右对齐，主题跟随系统，支持舒适/紧凑密度。
5. 大列表先采用分组分页；实测需要时再虚拟化。保留语义表格、键盘导航、可见焦点、读屏状态和 reduced motion。
6. 语言、主题与展开状态按明确范围保存；刷新不重置用户正在使用的控件。浏览器刷新/返回能恢复筛选。

完成条件：真实浏览器操作覆盖搜索、组合筛选、排序、跨页选择、代理展开、日期边界、长详情、远程管理与加载失败；结果与旧页面一致。组件替换与视觉调整分开验证；同一负载重新测量，不能只给 screenshots。

## 阶段 6：兼容发布与回退

操作：

1. 为支持的平台/架构发布预编译 Rust 程序与静态前端；开发工具链不成为用户运行依赖。
2. 保留 skills CLI 与 npm 安装路径、启动脚本兼容入口；二进制选择、校验、下载失败与离线提示明确。用户原配置和导入快照不随安装覆盖。
3. 索引按版本重建，升级期间保留可回退数据；旧版用户快照仍能导入，新版导出继续满足 v1 合同，若需升级格式先提供显式版本路径。
4. 发布前重跑本文件的正确性、性能和跨平台门禁，附原始报告。正式移除 Python 运行依赖的条件是支持矩阵全绿。

完成条件：从旧安装升级、首次安装、缺失依赖、端口占用、旧快照导入、索引损坏重建和回退流程均有可重放测试。最终 health 标识与发布制品一致。

## 阶段 7：后续 macOS / Windows 客户端

这是后续产品阶段，本次前置实验未实现或测量客户端。

1. Tauri 调用同一个 `usage-core`，前端增加 Tauri adapter。文件选择、打开目录、菜单、窗口、快捷键按宿主封装。
2. 先明确同一用户/数据范围的索引所有权。浏览器后台与桌面端共存时，共享单个索引写者或明确隔离 scope；不能靠两个进程各自监听来“自然同步”。
3. Windows 原生日志与 WSL 日志发现分开设计。访问 WSL 路径失败要明确状态，不能显示为零用量；沿用手动快照作为可用路径。
4. 在真实 macOS WKWebView 和 Windows WebView2 测冷/热启动、内存、滚动、长详情、休眠恢复、文件监听和 CPU 空闲占用；完成签名、更新、安装/卸载验证。

完成条件：浏览器与桌面同 fixture 结果一致；宿主切换只影响 adapter；原生平台报告独立列出，不能援引 Linux Chromium 结果当作通过。

## 性能验收门禁

这些是待实现目标，不是本次实验已经达到的产品指标。相对基线以同机、同数据、同构建模式、无竞争负载比较；亚毫秒路径以绝对时间和噪声评估，避免误用倍数。

| 路径 | 门禁 |
|---|---|
| 正确性 | token/身份/事件集合无差异；金额精度与 unknown 语义符合合同；任何正确性失败阻止发布 |
| Rust 核心 | 每个迁移模块都有对应基准；出现退化时记录原因并改进，不以其他模块的提升抵消 |
| 内存 | 同一工作量、同一统计口径下，缓存解码与快照合并峰值目标不高于 Python 基线 1.2 倍；超出时先减少通用 JSON、重复结果与同时驻留副本，再复测，不能用耗时收益直接抵消 |
| 无变化刷新 | 保留 204/no-render；本机 warm 路径无明显退化；WSL 历史缓存命中保持同等工作量 |
| 10k 事件详情 | 首次可交互 P95 <100 ms（约定机器）；分页与完整导出无遗漏 |
| 10k 会话搜索/展开 | 操作到更新 P95 <100 ms；搜索索引构建/更新开销计入首次或增量成本 |
| 完整扫描/追加 | 冷解析、持久恢复、单文件追加分别测端到端时间和峰值内存；Rust 发布前必须有实测值 |
| 常驻开销 | 无日志变化时无重复全解析；统计 5 分钟 CPU/内存与句柄趋势，不只测单次延迟 |
| 并发与一致性 | 4 客户端查询 + 活跃日志追加 + 远程导入时，无重复、丢失或跨 revision 混合 |
| 跨平台 | Linux/WSL、Windows 原生、macOS 分别检查文件、日期、启动与交互；未跑不能标完成 |
